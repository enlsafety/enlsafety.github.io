# Initial and annual risk assessments (r134)

Business-site navigation now offers 최초 위험성평가 (사업장 오픈 전 완료 필수) and 정기 위험성평가 (매년 1회 실시). These labels implement the requested company workflow; this change does not introduce or interpret statutory deadlines. Initial documents are scoped to the site; regular documents are additionally scoped to a selected calendar year. Each type offers five independently saved assessment books.

The supplied XLSX files were read without rewriting them. The normalized templates retain 204 numbered hazard rows: course 84, landscape 39, sprinkler 31, pest control 36, office 14. They retain all 12 task groups and the three improvement-before/after forms in each book. Source filenames and SHA-256 digests are in the template data. Merged-cell duplicate artifacts and hidden leftover template headings are not displayed. Opening a blank template does not create an evaluation record. Assessment date, risk level, action due/completion dates and actors remain blank until entered.

Field accounts can edit their authenticated site; safety can edit all visible sites. Manager and executive accounts share the same views with server-enforced read-only access. Base rows remain present and can be marked not applicable with an explanation. Users can edit the content and add/remove custom work rows. Drafts can be incomplete; completion requires an assessment date and evaluator, applicable tasks and ratings, reasons for excluded tasks, and measures/owner/due date for upper and middle ratings. Completion represents evaluation completion, not completion of all improvement actions or safety approval.

Private append-only revisions preserve previous saves and record the authenticated editor and server timestamp. Optimistic revision checks reject stale saves. The same site-folder lock coordinates saving with folder rename/hide actions. Folder hiding never deletes evaluations. Ordinary clients have no direct table access. Images are decoded client-side and resized for document display, accepted as bounded JPEG/PNG bytes and hash-deduplicated per site; original photograph retention is explicitly stated in the UI. Photo references are checked against that site's owned images. No production evaluation data was seeded or fabricated.

Validation: actual Edge handler with isolated PostgreSQL covered all roles, site/category/year isolation, drafts and completion validation, immutable history, stale revisions, image ownership/deduplication and folder hide/restore. DOM tests exercised type/book/year selection, edit permissions, unsaved-change protection, failed save retention and successful save/reopen for all four roles. Existing organization and incident lifecycle regressions and full-app dashboard/navigation tests passed. Production table grants/RLS and deployed Edge source were verified; unauthenticated HTTP requests remain rejected.

Browser limitation: preview tab creation failed with `Storage.setCookies: Invalid cookie fields`. Pixel layout, actual phone/Safari rendering, image decoding and print/PDF appearance have not been visually verified. DOM tests do not establish those properties.
