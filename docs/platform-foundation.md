# 통합시스템 운영 및 복원

운영 웹은 GitHub Pages의 `enlsafety/enlsafety.github.io` 저장소 `main`에서 제공한다. Vercel의 `enlsafety-ai-staging`은 별도 프로젝트다. PWA의 앱 식별자와 운영 도메인은 유지한다.

## 공통 계정과 직무

기존 본사 계정 `enl_hq_users`, 현장 인원 `enl_site_personnel`, 사업장 `enl_site_master`를 그대로 사용한다. 비공개 뷰 `private.enl_master_accounts`는 계정 출처와 원래 ID를 함께 제공한다. 비밀번호, PIN, 인증용 해시는 이 뷰의 조회 항목에서 제외한다. 사고 문서의 서명과 과거 스냅숏은 기존 사고 모듈에서 관리한다.

안전관리자는 시스템 관리에서 계정을 등록하거나 수정할 때 네 가지 업무 직무를 복수 선택할 수 있다. 직무 저장은 계정 저장과 같은 SQL 문에서 처리한다. 체크 해제 시 할당의 종료 시각을 남긴다. 실제 지정일, 해제일, 증빙 식별자용 필드는 별도 값이다. 체크한 날짜를 법적 선임일로 대입하지 않는다. 근거 규정은 산업안전보건법 제15조부터 제18조, 시행령 제14조부터 제22조 및 관련 별표를 확인한다.

## 모듈 및 이력

순서, 상태, 허용 역할과 시험 사용자 목록은 `private.enl_platform_catalog`에 저장한다. 시험 ID는 시스템 관리의 직무 담당자 화면에서 검색한다. 안전관리자 외에는 허용 역할 및 명시된 시험 ID가 모두 맞아야 구현 중 모듈에 들어갈 수 있다. 사고보고 카드 숨김은 별도 확인을 거친다. 이미 발송된 사고 문서와 결재 요청은 기존 권한으로 계속 처리한다. 다른 관리자가 먼저 저장하면 이전 설정을 덮어쓸 수 없다.

새 모듈은 서버 권한 검증 후 업무 저장 트랜잭션에서 `private.enl_platform_event`를 호출한다. 재시도에도 중복되지 않는 업무 이벤트 키와 발생 당시의 표시 문구를 전달한다. 이력에 원본 문서, 첨부파일, 인증정보를 복사하지 않는다. 새로운 모듈의 실제 문서 화면을 개발할 때 해당 모듈의 문서 열람 검사를 적용해 상세 링크를 연결한다.

정리는 표시 대상만 바꾼다. 안전관리자의 현재 비밀번호 확인, 실패 횟수 제한, 사유 입력을 거친다. 정리 감사기록에서 건수와 범위를 확인하고 해당 작업으로 정리한 기록을 복구할 수 있다. 이전 버전에서 이미 숨겨진 기록에는 작업별 복구 대상 목록이 없으므로 임의 복원하지 않는다.

## 배포와 복원 순서

1. 적용 전 본사 및 현장 계정, 사업장, 사고 원본의 건수와 내용 지문을 읽기 전용으로 대조한다. 운영 계정으로 로그인 시험을 하거나 운영 사고를 생성하지 않는다.
2. 추가형 마이그레이션을 적용하고 기존 서버와 웹을 그대로 사용할 수 있는지 확인한다. 신규 직무, 정리 작업, 카탈로그는 비공개 스키마에 있고 신규 테이블은 RLS를 사용한다.
3. 계정 API, 사고 동기화 API, 웹 순서로 배포한다. 운영 주소의 정적 파일과 서버 버전을 확인한다.
4. 화면 문제 시 이번 PR을 되돌려 이전 웹 소스를 더 높은 캐시 리비전으로 다시 배포한다. 기준 커밋은 `90f23f3169be8e825969a8b4a2e878fbd0521d66`이다. 기존 웹에서도 본사 및 현장 로그인은 같은 계정 원본을 사용한다.
5. 계정 API는 필요할 때 같은 기준 커밋의 로그인 v13, 현장 인원 v8 소스로 복구한다. 히스토리 정리 권한 강화를 유지하려면 사고 동기화 API는 신버전을 유지한다. 새 설정, 지정 이력, 정리 감사기록은 보존한다. 테이블 삭제나 사고 원본 전체 복원은 이 배포의 복원 절차에 포함하지 않는다.
