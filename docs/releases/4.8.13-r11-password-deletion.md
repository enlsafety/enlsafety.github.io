# 4.8.13-r11: 안전관리자 사고보고 삭제

## 변경 사항

안전관리자는 사고기록 상세에서 작성, 보고, 보완, 재발방지조치, 경영진 결재 대기, 종결, 과거사고 이관 상태에 관계없이 사고보고를 삭제할 수 있다. 삭제할 때마다 본인의 현재 로그인 비밀번호와 2~2,000자의 사유를 입력한다. 서버에서 활성 안전관리자 계정, 현재 로그인 인증, 새로 입력한 비밀번호와 사고 버전을 확인한다. 비밀번호 확인을 15분 내 5회 실패하면 재시도를 제한한다.

원본 사고 행과 사진/첨부파일, 결재본, 기존 이력은 물리적으로 삭제하지 않는다. 별도 비공개 삭제 원장에 삭제자, 시각, 사유, 사고 버전과 감사기록 ID를 기록하고 일반 목록과 통계에서는 제외한다. 사고 원본 감사기록과 삭제 원장 기록은 하나의 트랜잭션으로 저장한다. 일반 앱 접근자는 삭제 원장을 직접 조회할 수 없다.

삭제된 사고의 오래된 저장 요청은 DB에서 차단한다. 클라이언트는 서버의 삭제 ID를 받아 작성 중인 화면이 있어도 해당 사고를 목록과 캐시에서 제거한다. 이전 조회 응답이 늦게 도착해도 다시 표시하지 않는다. 삭제 이후 대기 중인 사고 알림은 발송 대상에서 제외하며 이미 발송한 알림은 회수하지 않는다.

- 앱/PWA 캐시: 4.8.13-r11

## 검증

- 실제 삭제/동기화 핸들러와 격리 PostgreSQL: 84개 검증 통과, 14개 사고 상태 포함
- 전체 앱 Chromium 화면: 94개 검증 통과, 320/390/820/1365px
- 기존 보고/보완/조치/종결 회귀: 44개 통과
- 경영진 결재 회귀: 53개 통과
- 푸시 인증/전송 조건: 58개 통과. 전송 서비스는 모의 처리
- 이메일 결재 단계/수신 정책/삭제 사고 발송 제외: 통과. 실제 메일 발송 없음
- 과거사고 후속조치 권한/첨부/이력/삭제 부모 조회 제외: 통과
- 동기화 경쟁 조건: 24개 통과. 실제 Edge/DB를 연결한 저장 충돌 테스트도 통과
- 현장 보고 입력 화면: 데스크톱, 320px, 412px 통과
- 별도 테스트 서버: 11개 검증 통과. 가상 종결 사고만 삭제 처리하여 원본, 감사 JSON, 삭제 원장, 목록 제외와 알림 미생성을 확인
- 운영 자료를 삭제하거나 실제 이메일/푸시를 발송하는 테스트는 수행하지 않음

실제 iPhone Safari 기기 테스트는 수행하지 않았다. 모바일 검증은 Chromium의 화면 크기와 터치 환경으로 수행했다. 삭제는 서버 기록 보존 방식이며 사용자가 직접 복원하는 새 기능은 이번 범위에 포함하지 않는다.
