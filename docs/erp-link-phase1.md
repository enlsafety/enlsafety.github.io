# 이앤엘 사고보고앱 × ERP 연동 1단계 (비운영 개발본)

## 기능 범위
- 사고보고앱의 **안전관리자**만, **사고 최종 종결 + 재발방지조치 승인** 건에서 ERP 연계 패널 이용.
- 기존 사고보고 Excel 다운로드 기능을 그대로 호출. ERP 기안은 사람이 수행하며 자동 업로드하지 않음.
- ERP 화면은 직접 열기만 함. 로그인 정보, 쿠키, AI 브라우저 세션을 수집하거나 ERP 내부 호출을 하지 않음.
- 사용자 확인을 거쳐 ERP 문서번호 및 수기로 확인한 상태를 별도 DB에 기록. **ERP 실시간 확인이 아닌 수기 기록**이라는 점을 표시.
- 이전 ERP 결재 사고를 이관한 과거사고는 신규 연계에서 제외.
- 사고 본문/사진/진단정보/결재선은 연계 DB에 저장하지 않음.
- 문서번호 중복·동시편집 충돌은 revision으로 검출, 전체 이력은 별도 감사 테이블에 보존.

## 환경별 적용
1. GitHub PR/개발 브랜치에서 코드·테스트 검토.
2. 스테이징 DB에 `sql/erp-link-schema-v1.sql`을 적용 (기존 테이블 수정 없음).
3. 스테이징 Supabase에 `edge-functions/enl-erp-link-v1/index.ts` 새 함수만 배포. JWT는 기존 앱 커스텀 계정 체계에 맞춰 비활성화하되, 본문 내 활성 안전관리자 암호 증빙 재검증.
4. 실제 ERP 내부 화면·문서 등록/조회 권한 확인 후 동작을 검증.
5. 운영 반영 전 개인정보 처리 범위, ERP 관리자 승인, 권한, 연동 기록, 롤백 경로 확인.
6. 운영 배포 때만 운영 DB에 스키마 적용 + 별도 함수 배포 + GitHub 메인 병합. **현재는 하지 않음.**

## 사용자 시나리오
1. 사고보고앱 → 최종 종결 사고 상세 → [ERP 전달].
2. [Excel 보고서 받기] (진료정보 등 개인정보 포함 가능, 회사 보안절차 준수).
3. [요약 복사] (민감정보 제외) → [ERP 열기] → ERP에서 직접 첨부하여 품의 진행.
4. ERP에서 실제 문서번호와 상태 확인 → [연계 기록 조회] → 문서번호·상태 수기 등록.
5. 미확인 상태는 승인완료로 표시하지 않음. 수정 시 연계 이력 별도 적재.

## 제한 및 주의
- API 기반 양방향 동기화, ERP 로그인 통합, ERP 문서 자동 기안/자동승인은 **미구현**.
- 기존 앱의 해시 인증증빙 체계를 그대로 쓰므로 클라이언트 XSS 보호, 계정관리, 서버 접근정책을 우선 준수해야 함. 앞으로 ERP 정식 SSO/API 제공되면 세션형 인증으로 교체 권장.
- 백엔드/DB 기능은 개발 브랜치에 따로 존재하며 운영 DB에 적용하기 전까지 운영 페이지에 표시하면 안 됨.
- 테스트는 가상 사건·계정 기준으로 수행. 운영 실데이터 변경·기안·발송 금지.
- ERP 운영 URL: https://erp.enlife.co.kr/ (로그인 이후 내부 기능은 별도 확인 필요).
