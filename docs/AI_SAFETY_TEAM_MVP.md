# 이앤엘 AI 안전관리팀 MVP

## 1. 최종 목표

이앤엘 안전보건 업무를 하나의 AI 조직으로 운영한다.

```text
             태영
              │
       ┌──────▼──────┐
       │ AI 안전본부장 │
       └──────┬──────┘
              │
   ┌──────────┼──────────┐
   ▼          ▼          ▼
법령검토    사고관리    위험성평가
에이전트    에이전트    에이전트
   │          │          │
   ▼          ▼          ▼
MSDS/화학   교육관리    문서/감사
에이전트    에이전트    에이전트
              │
              ▼
         최종검증 에이전트
```

1차 MVP는 복잡도를 줄이기 위해 아래 4개 역할만 실제 동작하게 만든다.

1. AI 안전본부장
2. 법령검토 에이전트
3. 사고관리 에이전트
4. 문서·최종검증 에이전트

위험성평가, MSDS/화학, 교육관리 에이전트는 2차 확장한다.

---

## 2. 1차 MVP 역할 정의

### AI 안전본부장
- 사용자 요청 또는 사고 이벤트를 접수한다.
- 어떤 전문 에이전트를 호출할지 결정한다.
- 전문 에이전트 결과를 취합한다.
- 상충되는 판단이나 근거 부족을 탐지해 재검토를 요청한다.
- 최종적으로 `자동처리 가능 / 태영 확인 필요 / 긴급 확인 필요`로 분류한다.
- 법적 책임이 수반되는 최종 판단은 사용자의 승인을 요구한다.

### 법령검토 에이전트
- 산업안전보건법, 시행령, 시행규칙 및 관련 공식자료를 우선 검토한다.
- 법적 의무 / 실무 권장 / 불확실 사항을 명확히 분리한다.
- 법령명, 조문, 기준일, 출처를 결과에 포함한다.
- 근거가 부족하면 추정하지 않고 `확인 필요`로 반환한다.
- 기존 사고앱의 `법정 보고 검토 필요` 플래그는 입력 신호로 사용하되 최종 법적 판단으로 취급하지 않는다.

### 사고관리 에이전트
- 사고보고 내용을 구조화한다.
- 사고유형, 상해정도, 휴업 예상, 즉시조치, 원인, 재발방지 후보를 정리한다.
- 누락정보와 모순정보를 탐지한다.
- 법령검토가 필요한 사건을 법령검토 에이전트에 전달한다.
- 사고보고 즉시성을 해치지 않도록 현장 작성자에게 과도한 입력을 요구하지 않는다.

### 문서·최종검증 에이전트
- 사고관리 및 법령검토 결과의 논리적 모순을 확인한다.
- 법적 의무를 단순 권고사항으로 잘못 분류하거나 그 반대인 경우를 탐지한다.
- 결과물의 필수 필드, 근거, 일자, 담당자, 후속조치가 빠졌는지 검증한다.
- 승인 전 결과를 읽기 쉬운 최종 보고 형식으로 정리한다.
- 검증 실패 시 안전본부장에게 반환하고 자동 확정하지 않는다.

## 3. 사고 1건의 기본 흐름

```text
현장 사고보고
  ↓
사고관리 에이전트
  ├─ 사고 사실관계 구조화
  ├─ 누락/모순 확인
  └─ 법령검토 필요성 판정
        ↓
법령검토 에이전트
  ├─ 최신 법령/공식자료 검토
  ├─ 법적 의무/권장/불확실 구분
  └─ 출처·기준일 기록
        ↓
문서·최종검증 에이전트
  ├─ 상호 모순 점검
  ├─ 근거 누락 점검
  └─ 최종 요약 생성
        ↓
AI 안전본부장
  ├─ 자동처리 가능
  ├─ 태영 확인 필요
  └─ 긴급 확인 필요
        ↓
태영 승인
```

## 5. 자동화 수준

### 자동으로 허용
- 사고 내용 요약 및 분류
- 누락정보 탐지
- 기존 데이터 조회
- 법령 후보 및 공식근거 수집
- 재발방지대책 초안
- 문서 초안 생성
- 검증 결과 생성
- 알림/승인대기 생성

### 사용자 승인 후 실행
- 법적 보고대상 최종 확정
- 사고보고 최종 승인/종결
- 외부기관 제출 문서 확정
- 기존 기록 수정 또는 삭제
- 대외 발송
- 고위험 작업의 최종 안전판단

## 6. 품질 및 안전 원칙

1. 법적 판단은 최신 공식근거를 우선한다.
2. KOSHA GUIDE와 내부지침은 법령과 구분한다.
3. 불확실하면 확정문구를 사용하지 않는다.
4. 모든 AI 판단은 누가, 언제, 어떤 입력으로 수행했는지 이력을 남긴다.
5. 에이전트가 다른 에이전트의 결론을 그대로 신뢰하지 않고 최종검증 단계에서 독립 검토한다.
6. 브라우저에 OpenAI API 키 또는 서비스 역할 키를 노출하지 않는다.
7. AI 백엔드는 별도 서버/서버리스 함수에서 실행한다.
8. 개인정보와 사고 민감정보는 필요한 최소 범위로만 전달한다.
9. 프로덕션 DB 변경은 승인 또는 명시적으로 허용된 자동화만 수행한다.
10. 기존 사고보고 앱의 정상 기능을 유지하며 AI 기능은 단계적으로 추가한다.

## 7. 기술 구조 제안

```text
[기존 이앤엘 사고보고 PWA]
          │
          │ HTTPS / JWT
          ▼
[AI Safety API]
          │
     AI 안전본부장
     ├─ 법령검토
     ├─ 사고관리
     └─ 문서·최종검증
          │
          ├─ OpenAI API
          ├─ 공식 법령/자료 검색
          └─ Supabase
               ├─ 기존 사고/사업장 데이터
               ├─ ai_workflows
               ├─ ai_agent_runs
               ├─ ai_findings
               └─ ai_approvals
```

프론트엔드에서 모델 API를 직접 호출하지 않는다. API 키와 관리자 권한은 서버 측에서만 보관한다.

---

## 8. 1차 구현 완료 기준

- [ ] 기존 사고보고 1건을 AI Safety API에 전달할 수 있다.
- [ ] AI 안전본부장이 사고관리 → 법령검토 → 최종검증 흐름을 실행한다.
- [ ] 결과가 구조화 JSON으로 반환된다.
- [ ] 결과마다 근거/불확실성/승인필요 여부가 표시된다.
- [ ] 모든 에이전트 실행이 DB에 기록된다.
- [ ] 앱 관리자 화면에서 AI 검토 결과를 확인할 수 있다.
- [ ] 사용자가 승인/보류/재검토를 선택할 수 있다.
- [ ] AI 오류가 기존 사고보고/승인 기능을 막지 않는다.
- [ ] 테스트 사고 데이터로 정상/누락/법령검토필요/충돌 케이스를 검증한다.

---

## 9. 2차 확장

MVP가 안정화되면 다음 순서로 확장한다.

1. 위험성평가 에이전트
2. MSDS/화학물질 에이전트
3. 교육관리 에이전트
4. 현장점검/사진분석 에이전트
5. 안전보건예산 에이전트
6. 정기 감사/미조치 추적 에이전트

최종적으로 AI 안전본부장이 이앤엘의 사고, 위험성평가, 교육, 화학물질, 점검, 예산 및 시정조치 데이터를 함께 보고 일일 안전업무 브리핑과 우선순위 업무를 제안하는 구조로 확장한다.
