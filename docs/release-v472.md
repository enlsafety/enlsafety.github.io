# 4.7.2 — 첨부 압축, 증빙 중복 제거, 공유 프로젝트 보안

릴리스 표기: `4.7.2-r2` / `stable-472-r2`. 이전 운영 기준 커밋은 `8d98345431556978225d68203e2f7ea353ad5a83`이다. 최초 최적화 운영 커밋은 `ac722c1b0b2e8785e4bd1c7f1c8642bc98c6568e`이다. r2는 계정 및 인사 API의 인증 증명 검증을 추가한다. 최종 운영 API 검증은 후속 기록에 반영한다.

## 변경 내용

- 신규 사진은 브라우저에서 원래 해상도를 유지하고 WebP/JPEG/PNG 후보의 실제 크기와 타일별 화질을 비교한다. 목표는 500KiB이며, 품질 기준 미달이면 압축을 약화하거나 원본을 사용한다. 원본 보존 체크, PDF 무변경, HEIC/HEIF 및 불확실한 색상, 고비트 이미지의 원본 보존 경로를 제공한다.
- 파일의 SHA-256, 원본 SHA-256, 크기, 해상도, 압축 정보를 보관한다. 서버는 실제 수신 바이트의 해시를 검증한다. 같은 사용자, 용도, 파일의 재시도는 동일한 불변 Storage 객체를 재사용하며, 기존 객체의 해시가 다르면 중단한다.
- DB의 새 첨부 참조에서 Base64와 임시 서명 URL을 제외한다. 이미지 확대, 화면맞춤, 원본크기, PDF 열람과 만료 URL 재발급은 유지한다. 정정 전 증빙도 역할별로 허용된 이력에서 확인하여 서명한다.
- 감사, 개정, 백업 JSON을 내용 해시 기반 사전에 보관하고 기존 행에는 참조 해시를 남긴다. 읽기 API는 원문을 복원한다. 이관은 기존 원문 해시와 재구성한 JSON의 동일성을 검증하며, 승인자, 시각, 사유, 문서 상태, ERP 정보와 이력 행을 삭제하지 않는다.
- 기존 Storage 정리는 별도의 고정 목록과 원본 백업, 바이트 해시, 전체 참조 검사를 통과한 완전 동일 파일만 대상으로 한다. 기존 증빙의 손실 압축을 자동 시행하지 않는다.
- 지정된 콕매치 5개 테이블의 RLS 변경과 서버 인증 검증은 별도 보안 이관으로 관리한다. 최종 적용, 회귀검증 상태는 아래 표에 기록한다.
- 데모의 메모리 첨부 API를 새 업로드 응답 구조에 맞춰 수정했다. 데모는 외부 API와 연결하지 않는다.

## 복구 순서

1. 이관, 정리 작업을 중지하고 복구할 시점의 배포 커밋, DB 원문/연결정보 백업, Storage 원본 목록과 해시를 확인한다. 복구 중 새 증빙 쓰기가 섞이지 않도록 관리한다.
2. **이력을 원래 JSON 열로 완전히 재구성하고 검증한 뒤에만 구형 Edge 읽기 코드를 복구한다.** `tests/fixtures/evidence-storage-rollback.sql`의 검증된 순서를 운영 테이블에 적용한다. 압축 INSERT 트리거 제거, 해시 검증을 통한 모든 이전/이후/변경/백업 원문 복원, 동일 원문만 허용하는 활성 보호 트리거와 기존 변경금지 트리거 복원, 필수 제약 복구를 한 트랜잭션으로 처리한다. 원문 해시와 결재, 정정 조회를 다시 검증한다. 사전과 해시는 즉시 삭제하지 않는다.
3. Storage 연결을 이전 경로로 되돌릴 때는 **먼저 원본 바이트를 이전 경로에 복구하고 크기, SHA-256을 검증한 후** DB 경로를 되돌린다. 복구 중 현재 경로의 객체를 제거하지 않는다. 서명 URL과 이력의 미리보기를 확인한다.
4. 복원된 DB와 호환되는 이전 Edge 버전을 배포한 후 이전 프런트엔드 파일을 복구한다. 서비스워커 버전과 캐시 갱신 식별자는 새로운 값으로 올려 이전 파일이 모든 클라이언트에 다시 설치되게 한다. 공개 파일 해시, 로그인, 역할별 사고, 사진 조회를 확인한다.
5. 보안 정책은 다른 앱 권한을 확대하지 않는 범위에서 변경 전 백업과 비교해 개별 복구한다. 앱 오류 해결을 위해 RLS 전체를 무조건 해제하지 않는다.

## 확인하지 못한 범위

Linux WebKit/모바일 화면 크기 검사는 실제 iPhone 또는 macOS Safari 기기 검사를 대체하지 않는다. 실제 HEIC 디코딩 성공, 실제 기기 PWA 설치, 카메라, 멀티터치와 모든 Safari 버전은 미검증이다. 지원하지 않는 디코딩 경로는 원본 바이트 보존을 확인했다. 자동 화질 지표와 대표 표본의 시각 확인만으로 모든 미세 증빙의 판독성을 보증하지 않으므로, 정밀 증빙은 원본 보존을 선택한다. 불명확한 보존 의무, 참조 관계의 자료는 삭제하지 않는다.

운영 실제 사용자 세션으로 콕매치 로그인 후 조작하는 시험은 하지 않았다. 기존 공용 모임 PIN과 모임장 이름을 함께 허용하는 인증 경로는 이번 RLS 수정에서 변경하지 않았으며 별도 보완이 필요하다. 과거 Base64 증빙 3개의 고유 원본은 정확한 문서 복원을 위해 비공개 증빙 사전에 한 번씩 보존한다.

기존 공개 코드에 포함되었던 관리자 인증값은 제거했지만, 이미 노출된 값을 무효화하려면 관리자 비밀번호 교체가 필요하다. 운영 접속을 임의로 바꾸지 않기 위해 비밀번호 회전은 수행하지 않았다. ID만 확인하던 서버 코드로 되돌리는 복구는 보안 취약점을 다시 열 수 있으므로 피한다.

최종 r2 전체 검증은 65개 스위트가 통과했다. 신규 로그인 브라우저 시험의 WebKit 가상주소 탐색 오류는 로컬 루프백 페이지와 오프라인 시험 방식으로 수정했고 Chromium과 WebKit 각각 18개 항목을 재검증했다. 시험용 데이터만 사용했고 외부 인증정보 전송은 없었다.
