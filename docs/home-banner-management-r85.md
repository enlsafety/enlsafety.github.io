# Home banner management (r85)

- Fixed 10-second carousel cadence. Arrow/dot/touch/keyboard interactions, pointer hover and retained button focus do not reset or stop the timer. Reduced-motion users get instant transitions. Hidden pages do not animate; timers are cleaned up when detached.
- Safety-only System management > Banner management replaces the history shortcut. Shared history remains available through common services.
- Configure 0–12 ordered slots. Zero hides the hero. Choose preserved built-ins or upload JPG/PNG/WebP (5 MiB maximum; landscape 320×80 minimum, 8192px per side and 30MP maximum). Suggested desktop art 1920×400. Contain is default; cover is optional. Desktop/mobile preview before publishing.
- Uploads are immutable private objects in `enl-incident-files/home-banners/`. Existing bucket access and incident policies remain unchanged. Metadata, configuration and revision audit are private server-only tables with RLS and no anonymous/authenticated table grants. APIs validate the verified actor and system-service access. Reads sign only configured asset IDs; browser-supplied storage paths/URLs are never accepted.
- Uploading does not publish. Save uses a row lock and optimistic revision; conflicting changes do not overwrite newer settings. Removing slots retains original files. Existing built-ins are seeded unchanged; the 2026 health campaign still expires after 2026-12-31 Seoul time.
- Validation: actual Edge handler + isolated PostgreSQL passed 29 banner checks; incident lifecycle 44 checks; platform-foundation, integrated-home-content and release/cache regressions passed. Chromium fixtures passed 17 carousel checks at both 1365px and 390px, and 13 editor checks at desktop/mobile widths, including drag-upload preview, reorder, conflict retention and save. Storage responses are mocked in isolated tests; production authenticated upload has not been exercised with user credentials.
