# 사고보고앱 데모 임시 중단

2026-10-29, stable-473-r2에서 데모 관련 화면을 임시 숨김 처리했다.

- `auth-v411.js`의 `DEMO_ENABLED=false`는 로그인 화면의 데모 링크를 생성하지 않는다.
- `zerowiz-demo.html`과 `zerowiz-demo-app.html`은 일반 로그인으로 이동하는 페이지다. 기존 역할 선택, 비밀번호 입력, 데모 관리 및 초기화 화면을 불러오지 않는다.
- 두 HTML 원본은 이 폴더의 `.html.txt` 파일로 그대로 보존했다. 실행 페이지로 사용하지 않는다. 나머지 데모 JS와 CSS는 기존 경로에 보존했다.
- 서비스워커와 로그인 스크립트의 캐시 식별자를 갱신했다. 기존에 열린 화면에는 다음 재실행 또는 새로고침부터 적용된다.
- 운영 DB, 사용자 계정, 사고자료, 승인 흐름은 변경하지 않았다. `u-safety-demo`는 운영 안전관리자 계정 식별자이므로 삭제하거나 비활성화하지 않는다.

## 다시 열 때

1. 현재 운영 UI와 보존된 데모 소스의 버전 차이를 검토한다. 격리, 가상 자료, 네트워크 차단을 유지한다.
2. 두 `.html.txt` 파일을 각각 루트의 `zerowiz-demo.html`, `zerowiz-demo-app.html`로 복원한다.
3. `auth-v411.js`의 `DEMO_ENABLED`를 `true`로 바꾼다.
4. 빌드, 로그인 스크립트 및 서비스워커 캐시 버전을 새 값으로 올리고 관련 검증의 운영 상태 기대값을 갱신한다.
5. 로그인, 데모 비밀번호, 5개 역할, 운영 서버 연결 차단 및 모바일 화면을 검증한 뒤 배포한다.

`tests/zerowiz-demo-security.cjs`와 `tests/zerowiz-fidelity-browser.cjs`는 보존된 원본을 대상으로 격리 검증을 계속한다. 후자는 테스트 내부에서만 `.txt` 원본을 가상 페이지 응답으로 사용하며 공개 데모를 재개하지 않는다.
