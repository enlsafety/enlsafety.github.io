# 4.7.0 — 누적 사고보고서

## 변경 이유

기존 A 편집기가 reportDetails를 다시 조립하면서 B의 원인분석을 누락했고, 승인된 사고에도 일반 재제출 저장 경로가 연결되어 있었다. 후속 팝업은 서로 다른 요약 양식을 사용했고 일부 화면 장식 코드가 다른 단계의 입력값을 변경했다. 완료일은 화면에 표시되지만 서버 허용 필드에 포함되지 않았다.

## 구현

- report-v410의 기존 A 양식을 편집·읽기전용에 공동 사용한다. 같은 사고 ID에 A/B/C/D/E를 순서대로 표시한다.
- 수정 시 서버 버전을 고정한 스냅샷을 사용하고, 기존 미입력값·특수 사고유형·한국시간 및 과거자료의 시간 미상 표식을 보존한다.
- 승인 전에는 기존 push, 승인 후에는 correct_closed와 감사 개정이력을 사용한다. 과거사고 재인증과 ERP 원자료 정보 수정도 유지한다.
- C/D/E 팝업은 현재 작성·검토 영역에 한 번만 스크롤하며 입력 포커스를 이동하지 않는다. C/D 탭 초안은 사용자·사고·서버 버전별로 보관한다.
- 서버가 조치 제출본과 보완요청 이력을 누적한다. 승인·회수 경합, 무단 변경, 제출 증빙 조작 및 잘못된 완료일을 거절한다.
- 최종 Excel은 A~E 보고서 1개 시트와 첨부 시트를 생성한다. A4 여백·인쇄영역·열 너비·줄바꿈·수동 페이지 나눔을 설정한다. 통계/목록 내보내기는 변경하지 않았다.
- 데모는 동일 운영 폼의 submit 이벤트를 가상 백엔드에 전달한다. opaque sandbox, form-action none, connect-src none 및 메모리 저장 격리를 유지한다.

## 검증 범위

독립 PostgreSQL과 실제 Edge handler, Chromium 및 WebKit(PC/Android/iPhone/태블릿 크기), 전체 운영 스크립트를 사용한 격리 데모, 서버 재조회, 역할·알림·첨부·과거사고 회귀검사를 수행한다. XLSX는 Chromium/WebKit 다운로드와 ZIP/XML/openpyxl 구조 검사, CI LibreOffice A4 인쇄 검사로 검증한다. 실물 모바일 기기와 Microsoft Office 2019 자체 실행은 별도 확인 대상이다.

## 배포 및 복구

DB 마이그레이션이나 운영 사고자료 갱신은 필요 없다. JSON payload 안에 서버 소유 submissions 배열이 추가된다. 운영 반영 전 격리된 QA Edge와 가상 데이터에서 검증한다. 프런트엔드 캐시는 stable-470-r1로 갱신한다. 장애 시 이전 GitHub 커밋을 복구하고 이전 Edge 소스를 재배포할 수 있으며 신규 제출·감사 데이터는 삭제하지 않는다.
