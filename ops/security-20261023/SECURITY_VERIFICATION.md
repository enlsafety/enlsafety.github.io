## 적용 및 확인

- 운영 변경은 지정된 5개 테이블의 RLS 활성화와 anon/authenticated/PUBLIC 권한 회수로 한정했다. 기존 service_role 권한과 postgres 소유권을 유지했다.
- 현재 콕매치 v6.91 프런트 소스 HEAD 605e10e361f011439b2f94fd7e8c6401b9f00575는 이 테이블을 브라우저에서 직접 읽지 않는다. 커스텀 세션을 검증하는 Edge API가 서버 DB 연결 또는 service_role로 접근한다.
- 운영 보안 진단에서 rls_disabled_in_public 항목은 5건에서 0건으로 줄었다. RLS enabled/no policy 안내는 서버 전용 테이블의 의도된 차단 상태다.
- 운영 5개 테이블의 행 수 및 전체 내용 정규화 SHA-256이 변경 전과 정확히 일치한다. 원본 자료를 삭제하거나 변경하지 않았다.
- 실제 Chromium에서 운영 앱 출처를 통해 요청한 직접 REST 접근은 변경 전 5개 모두 HTTP 200, 변경 후 5개 모두 HTTP 401이다. 조회에는 limit=0을 사용하여 실제 개인정보를 반환받지 않았다.

## 테스트 환경

기존 테스트 프로젝트에는 콕매치 테이블이 없었다. 최초 `information_schema.tables WHERE table_name LIKE 'kokmatch%'` 조회 결과는 빈 배열이었다. 기존 운영 API 4개를 테스트 프로젝트에 별도 이름으로 복사하고, 가상 회원/모임장/관리자와 가상 모임을 생성했다.

- 변경 전 22/22 통과, 변경 후 22/22 통과.
- 회원/모임장/관리자 로그인, 상태 조회, 소속 모임 조회를 각각 확인했다.
- 관리자 모임 조회와 수정 및 원상복구를 확인했다. 일반 회원과 모임장의 전체 모임 관리 접근은 HTTP 403이었다.
- 비로그인 API 접근은 HTTP 401, 5개 직접 테이블 접근은 적용 후 HTTP 401이었다.
- 각 상세 결과는 동봉된 before_api_results.json, after_api_results.json에 있다.

## 정리 상태와 한계

- 테스트용 Edge API 4개는 버전 2에서 DB 연결을 제거하고 HTTP 410만 반환하도록 폐기 처리했으며 실제 HTTP 410 응답을 4개 모두 확인했다.
- 운영 health 200, 비로그인 상태/관리/인증 요청 401, 존재하지 않는 가상 회원 조회 401을 실제 API에서 확인했다. 운영 요청 5개와 폐기 API 4개 총 9/9 통과했다.
- 이번에 생성한 가상 테이블 8개는 2026-10-23 고정 대상 정리 실행기로 제거했다. 실행기는 테스트 프로젝트·지정 4개 사고 ID·8개 테이블만 허용하고, 변경 전 전체 내용·스키마 해시와 가상 식별자를 검사한 뒤 한 트랜잭션에서 처리했다. 독립 읽기 전용 SQL 검증(07:04 UTC)에서 8개 테이블 부재, 관련 없는 QA 행의 건수·해시 일치 및 보호 트리거 복원을 확인했다. QA 증빙 사전 671개는 검증 증거로 그대로 보존했다. 요약은 `../staging-cleanup-20261023.json`에 있다. `cleanup_staging_pending.sql`은 최초 계획의 참고 기록이며 다시 실행할 대상이 없다.
- 운영의 실제 회원 및 관리자 세션 토큰을 보유하지 않아 운영 로그인 후 화면 조작은 실행하지 않았다. 역할별 정상 흐름 검증은 테스트 환경 결과다.

- 기존 login-v33 소스는 모임장/운영진 이름에 공용 모임 PIN도 허용한다. 소스에서 확인한 기존 인증 동작이며 실제 운영 사칭 시험은 하지 않았다. 개인 PIN 강제 여부는 별도 인증 흐름 검토가 필요하다. 따라서 이 작업은 콕매치 전체 인증체계의 안전성을 보증하지 않는다.
- 추가 SQL 역할별 60개 단언 검사는 도구 호출 지연으로 완료 여부가 확인되지 않아 통과 수에 넣지 않았다.
